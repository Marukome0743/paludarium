# U1 hello-cの追加SSE命令と差分回帰

## 観測

検証済み：Ubuntu musl1.2.4のhello-cがlegacy XMM MOVQ（`66 48 0f 6e c0`）でInvalidOpcodeとなった。実装前のnative期待結果とSSE差分Redはintent記録の`verification/native-expectations-37672366086.log`、`native-red-bookworm-37672366086.log`に保存している。

## 対応

`tests/guests/insn/sse.c`でMOVQの上位64bitゼロ化、PUNPCKLQDQの異なる入力値・自己参照をnative差分で確認する。検証済み：修復後のIntel/AMD実機のU1差分16件が通過（run37674781864のworkspace/bookworm jobs）。

`crates/paludarium-harness/src/coverage.rs`の命令対応表は従来66件へMOVQ/PUNPCKLQDQを追加し68件とした。helperは68/68を確認するが、これは対応するゲストのソース根拠片がある割合であり、全operand・flags入力の意味論網羅率ではない。以前のcensusファイルは当時のビルドの履歴として保持する。
