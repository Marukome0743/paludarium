**Security of the first-publication token path (checked against the diff):**

- Tokens exist only in the `publish` job, which has `environment: release`. The hand-off requires environment secrets, not repository secrets.
- `authorize` discards any `registries_absent` or `registry_presence` value from the evidence document. Only the live 200/404 query can set it. Any other HTTP answer, or an unreachable registry, stops the run.
- `authentication()` rejects the conflicting declaration (both flags true), and rejects "first" without a live absence result.
- `publish_artifacts` calls `authorize` again, so the absence check is repeated at upload time.
- If the OIDC step is skipped but the publish step derives `oidc`, the OIDC token is absent and the run stops. This fails safe.
- In OIDC mode, leftover first-publication secrets stop the run.
- Receipts keep only a whitelist of non-secret environment keys. Tokens are never written to results or progress files.

### Summary

The first-publication and OIDC paths are gated by a live registry check, the tokens are kept apart per upload command, and the claimed test, validation, and CI numbers are backed by the run output and the recorded evidence. The one design concern that remains is the missing recovery for a partially completed first publication, which the absence gate turns into a dead end. This is recorded as a Major finding to resolve before the real publication. With one Major, zero Critical, the review is READY.
