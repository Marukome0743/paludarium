**Bolt** とは、1 つの Unit を設計からコードまで通して作り、動くものを出すひと区切りです。

## 使った考え方

1. **細い一本を先に**（Cockburn の walking skeleton）
   - 最初の Bolt は U1 に固定します（team-practices の Walking Skeleton）。
   - walking skeleton とは、全体を最初から最後まで通す最小の版のことです。
2. **リスクを先に**（Boehm のスパイラルモデル）
   - U1 の後は、リスクの大きいものを先にします（Q1）。
   - 一番の心配は 2 つです（Q6）。1 つは wasm でマルチスレッドが作れるか、もう 1 つは命令の意味の誤りです。
3. **WSJF で点数を付ける**（Reinertsen の CD3 と SAFe の WSJF）（Q2）
   - WSJF は Weighted Shortest Job First の略で、点数は（価値 ＋ 急ぎ ＋ リスクを減らす大きさ）÷ 作業量です。
   - 点数が高いほど先に作ります。
   - 依存が済んでいないものは、点数が高くても先にしません。

## 点数の付け方

- **価値・急ぎ・リスク**：それぞれ 1〜10 で付けます。
  - リスクの点は「この Bolt で心配が晴れる大きさ」です。Q6 の心配（wasm のスレッド、命令の意味）に関わるものを高くしています。
- **作業量**：Unit の大きさを数字に置き換えます（S=1、M=2、L=3、XL=4）。
- **注意**：点数は判断による見積もりで、精度は低いです。U1 の実績で見直します。

## 並べ方

各時点で依存の済んでいる Unit のうち、点数の高いものを選びました。

- **U1 の後**：選べるのは U2・U4・U7・U9 です。点数が一番高い U4（9.0）を選びました。
- **U4 の後**：U5 は依存の上では選べます。しかし U5 は、原子的な命令（lock 接頭辞付きの命令など）を必要とします。その担当は U2 です（作業単位のレビュー指摘 R-01）。そこで先に U2 を作ります。依存関係の文書より厳しくした並べ方で、下の「依存関係からのずれ」に記録しています。
- **U2 の後**：U5（8.0）、その後 U6（10.5）の順です。
- **U6 の後**：U9（7.0）、U3（7.0）、U7（6.5）、U8（7.0）の順です。
  - U9 と U3 は同点なので、作業量の小さい U9 を先にしました。
  - U8 は U7 に依存するので、U7 の後にしました。
- **U10**：段階 2 のまとめです。それまでのすべてに依存します。
- **U10 の後**：点数では U12（6.0）、U11（6.5）、U13（5.7）が並びます。ここは Q1・Q6 の回答に合わせて、点数より次の判断を優先しました。
  - **U11（wasm）を先に**：一番の心配（wasm のスレッド）に答えるためです。
  - **U13（Windows）を U12（macOS）より先に**：Q1 で「差の大きい Windows を先に」と答えたためです。点数（5.7 と 6.0）とは逆の順番で、下の「点数からのずれ」に記録しています。
- **U14（JIT）**：U11 の後です。
- **U15（公開）**：最後です。

## 依存関係からのずれ

| 内容 | 理由 |
|------|------|
| U5 の前に U2 を作る（依存関係の文書には U5 から U2 への依存がない） | U5 のゲスト（musl のスレッド）は原子的な命令を使い、その担当が U2 のため（作業単位のレビュー指摘 R-01） |

ほかは、依存関係の文書の並べ方の 1 つです。

## 点数からのずれ

| 内容 | 理由 |
|------|------|
| U11 を U12 より先にする | 一番の心配（wasm のスレッド）に早く答えるため（Q6） |
| U13（5.7）を U12（6.0）より先にする | 差の大きい Windows を先にする方針（Q1） |

## リスクへの手当て

| リスク | 手当て | 関わる Bolt |
|--------|--------|-------------|
| wasm でマルチスレッドが作れない（RAID ログ R2、Q6） | U1 で小さく確かめ、結果を U1 の完了条件で報告する。結果が悪ければ、U4・U5 の前に Mmu・Host の trait・C2・C4 を見直す（Q7） | B1、B2、B4、B11 |
| 命令の意味の誤り（RAID ログ R1、Q6） | U1 から差分テストを作り、U2・U3 で命令ごとに確かめる | B1、B3、B7 |
| Windows で Linux を再現できない（RAID ログ R3） | macOS より先に作り、早く気づく | B12 |
| 長期化して止まる（RAID ログ R4） | 1 Unit を 1 Bolt にして、毎回動くものを出す | すべて |
| aube を static-musl でビルドできない | B10 で確かめ、だめならそこで扱いを決め直す | B10 |
